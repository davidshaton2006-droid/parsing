# PROJECT_HISTORY.md — происхождение правил

## Контекст
18–19 ноября 2026 года в чате «Создание сайта GT Service» создавались три самостоятельных демонстрационных продающих сайта под автосервисы Краснодара. Их задача — показывать потенциальным B2B-клиентам готовый вариант премиального сайта вместо абстрактных обещаний разработки. Позднее пользователь закрепил правило: все следующие сайты должны публиковаться через один существующий публичный репозиторий davidshaton2006-droid/parsing, каждый в собственной подпапке и со своей ссылкой.

## Исходные демо и принятые решения
1. **GT Service** — Краснодар, Алма-Атинская, 2/15. Мультибрендовый автосервис; фирменный характер тёмный графит, белый, красный акцент, контрастная типографика, диагностика и ремонт. Ранее делали «GT_Service_Premium_Demo», затем «GT_Service_Fixed_v2» — исправляли видимость контента без JS, контраст и поведение блоков. В демо присутствуют услуги, фото, сценарий записи, контакты, карта, отзывы/сигналы доверия; сведения и цены перед коммерческим запуском перепроверять. Карточка: https://yandex.ru/maps/org/gt_service/101778782759/
2. **Альфа Авто** — Краснодар, проезд Репина, 16. Отдельный адаптивный премиальный концепт, сценарии записи/обращений, демонстрационные цены. Карточка: https://yandex.ru/maps/org/alfa_avto/150783041328/
3. **RIA-Service** — Краснодар, Красных Партизан, 2/1. Профиль VAG: Volkswagen, Audi, Škoda, SEAT. Отдельный HTML-проект с Motion и progressive enhancement, визуальной и конкурентной проработкой. Карточка: https://yandex.ru/maps/org/ria_service/1300546382/

Старые ZIP/HTML-файлы могут храниться в ChatGPT Library, но НЕТ гарантии, что другой агент автоматически получит к ним доступ. Текущий источник истины для опубликованных версий — репозиторий parsing.

## Ошибки и уроки
- Изначально три проекта готовились как автономные HTML/ZIP для статического хостинга. Затем договорились об общей публикации через GitHub Pages.
- Запуски GitHub Actions падали на Configure Pages с «Get Pages site failed / HttpError: Not Found». Исправление было в настройке Settings -> Pages -> Source: GitHub Actions; пользователь подтвердил, что после этого все три сайта опубликованы.
- В первоначальном deploy-pages.yml on.push.paths был перечислен вручную: index.html, gt-service/**, alfa-auto/**, ria-service/**, .nojekyll, workflow. Это НЕПРАВИЛЬНО для постоянного добавления новых клиентов: workflow необходимо сделать универсальным.
- Основное содержимое страницы никогда не должно ждать JS: ранние проблемы с reveal-поведением потребовали исправлений.
- Нельзя говорить, что CRM/бронь работают, если форма лишь подготавливает WhatsApp-сообщение для отправки пользователем. Дата/время не являются подтверждением свободного слота.
- Нельзя объявлять фиктивные отзывы, цены, награды, гарантии, фото и рейтинги подлинными. Для неподтверждённых данных — честная демонстрационная маркировка.
- Фотографии в первом экране могут быть иллюстративными, но посетитель должен понимать их статус, если они не показывают реальную компанию.

## Изменения в будущем
Разрешено улучшать методику, дизайн и стек, но сохраняй фундаментальные требования: индивидуальность/качество, достоверность, доступность без JS, практичная анимация, рабочие формы и один репозиторий с отдельными путями для каждого клиента.
